# Alpaca options backfill — replace synthetic chain with real EOD data

Status: DRAFT v2 — pending acknowledgment
Drafted: 2026-05-01 (revised after consulting go-architect, quant-analyst, qa-inspector)
Branch target: main
Scope: Feb 2024 to present. Pre-Feb-2024 history out of scope.
Principles: SOLID (single-responsibility per service, no speculative interfaces) + KISS (concrete types, defensive skip-don't-default, smallest viable diff).
Related: `synthetic_options_chain.go` (chain source we are retiring), `optionsimport/service.go` (existing DoltHub importer to be peer-aligned).

## Problem

Backtest P&L on every recent date is generated by the synthetic chain. Smoke test on 2026-04-30 (avwap_v4 + macd_only_v1, full universe): 16 trades / $2,117 with synth ON, 0 trades / $0 with synth OFF, `historical_hits=0 / synthetic_hits=20` either way. The backtest path is trading a chain that does not exist in the live OPRA market.

Quant-analyst confirms: real-strike-list realism is ~80% of the win available from this work. Print-vs-mid noise, heuristic spread, and locally-derived greeks each contribute single-digit percent additional realism — fix only the strike list this round.

## Decision: free Alpaca path, derive greeks/IV locally

Account already has paid Alpaca with OPRA real-time. Historical bars are exposed identically on free and paid tiers; paid tier improves only the live-snapshot path (already wired). Alpaca historical exposes OHLC bars only — no historical greeks, no historical bid/ask snapshots. We invert IV from the EOD trade close via Newton-Raphson, then forward-compute greeks at that IV.

Quant validation: IV error vs true 16:00 mid is ~1-2 IV pts on liquid weeklies, ~3-8 on illiquid; resulting delta error is ~0.01-0.06, well inside the strategies' 0.15-wide delta bands. Selector picks should match a paid vendor (ORATS) >85% of the time within the delta band.

## Architecture

Two ingest paths into the same `historical_option_chain` table. Each is a single-responsibility service with a concrete method, no shared interface (KISS).

Path A — forward capture (daily, runs in omo-data)
- Trigger: 16:30 ET, alongside the existing IV collector at `omo-data/main.go:189`.
- Plus startup catch-up: on omo-data start, run forward capture for any of the last 5 trading days where `historical_option_chain` has < 50% of trailing-30-day median row count for the universe.
- For each universe symbol: `alpaca.GetOptionChain(underlying, expiryFrom=today, expiryTo=today+60d, right=C and P)`. Live snapshot endpoint already returns bid/ask/IV/greeks/OI — no derivation needed for forward rows.
- Persist via `HistoricalOptionsRepository.SaveBatch`. Idempotent (`ON CONFLICT DO NOTHING` confirmed at `historical_options_repo.go:205`).

Path B — historical backfill (one-shot, omo-backfill CLI)
- New flag: `omo-backfill -source alpaca -from 2024-02-05 -to <date>`.
- One-shot run, no daily catch-up job — Path A's startup patch covers any going-forward gaps.
- Per (symbol, date):
  1. Enumerate OCC contracts: `/v2/options/contracts?underlying_symbols=SYM&expiration_date_gte=DATE&expiration_date_lte=DATE+60d&status=active` (Alpaca-API issue #262: expired contracts return as `status=active`, exactly what we need for past dates).
  2. For each OCC: 1-day bar at DATE via `/v1beta1/options/bars`.
  3. Underlying close from existing `bars` table.
  4. Newton-Raphson BSM IV inversion (4-6 iters to 1e-6, the algorithm is in scope for `internal/app/options/bsm.go`, see "Code organization" below).
  5. Forward-compute delta/gamma/theta/vega at the implied IV.
  6. Spread = per-symbol pct from `cfg.OptionsBackfill.SymbolSpreadPct` map (calibrated once from live snapshots; fallback default 0.05).
  7. **Skip the row entirely** when: BSM inversion fails to converge, the option close is at the 0.01 floor (zero price information), or any required input is NaN/Inf. Do NOT write a fallback row — write nothing. This protects the contract picker from divide-by-zero / silent-zero-delta bias (qa-inspector HIGH-1, HIGH-2).
- Concurrency: 8 symbol workers, throttle to 800 req/min (1000/min cap with headroom). Resume by skipping (symbol, date) pairs where row count exceeds a sentinel (50 rows). Wall time estimate: ~2.5h for 2024-02 → today on the 34-symbol universe.

## Defensive design (qa-inspector HIGH findings)

1. **Skip-don't-default**. If BSM inversion fails or input is degenerate, write nothing. Picker sees no row instead of a synthetic-IV-0.20 row that would silently bypass the `max_iv=1.2` filter. This is simpler than adding a `min_iv` floor to every strategy TOML.

2. **Greek/IV provenance via NULL semantics**. `historical_options_repo.go:267 nilIfZero` writes NULL for any zero. We will NOT rely on NULL-vs-0 for "data missing vs derived" because the picker can't tell the difference. Skip-don't-default eliminates the question.

3. **No new provenance column**. Two sources (DoltHub + Alpaca) will sometimes write the same (date, symbol, expiry, strike, right). `ON CONFLICT DO NOTHING` means whoever wrote first wins. For Feb 2024+ that's predominantly Alpaca because we backfill before DoltHub catches up; for monthlies on overlapping dates DoltHub wins. Greeks may differ slightly between sources. Documented and accepted — schema change not justified by current value (KISS). If we ever need a swap, `DELETE` then re-write.

## Per-symbol spread heuristic

User direction: per-symbol, not four-band underlying-price-band.

Implementation: `cfg.OptionsBackfill.Alpaca.SymbolSpreadPct map[string]float64` keyed on underlying. Calibration: one-shot job (separate from this plan, ~30 min wall time) samples today's live OPRA snapshots for each universe symbol over a few weekly DTE buckets, takes the median spread%, writes to YAML. Fallback `default_spread_pct = 0.05` for symbols not in the map.

YAML shape:

```yaml
options_backfill:
  alpaca:
    enabled: true
    dte_range: [0, 60]
    max_concurrency: 8
    default_spread_pct: 0.05
    symbol_spread_pct:
      AAPL: 0.025
      TSLA: 0.020
      IWM: 0.025
      MU: 0.040
      AFRM: 0.060
      RBLX: 0.060
      SOFI: 0.080
      # ... 27 more rows for the trading universe
```

Rationale: avoids the four-band approximation (quant flagged AAPL/IWM band overestimates by 2-3x). One-shot calibration is cheap; if a name's spread changes structurally we update YAML. KISS — no auto-recalibration loop.

## Prerequisite: synthetic_chain config-loader bug fix (separate PR, ships first)

`backend/internal/config/config.go:864-869` silently flips `Enabled = true` whenever the YAML user sets `enabled: false` without overriding any other field. The omitted-detection check is wrong:

```go
omitted := !c.Enabled && c.StrikeGridPct == 0 && ...  // <-- !c.Enabled is the bug
```

Fix: drop `!c.Enabled` from the omitted check. Detection should be "user provided no synthetic_chain block at all", not "user set enabled false and omitted other tunables". One-line change + a unit test. go-architect flagged this as not belonging buried in Phase 3 — it's a prerequisite. Ship as a small standalone PR before Phase 1 of this plan.

- If parity passes: ship. If not: investigate, keep synthetic as a fallback flag rather than removing the code.

## Out of scope

- Pre-Feb-2024 history (paid vendor required; explicitly out per user direction).
- Real historical bid/ask quote snapshots (Alpaca doesn't expose them; spread is heuristic). Quant flagged this as the next thing worth fixing if backtest realism still diverges from live after this lands.
- Alerting plumbing for backfill drift detection. Catch-up patch on startup + a WARN log when today's row count is <50% of trailing-30-day median is sufficient ongoing signal. KISS — no PagerDuty integration.
- Time-varying risk-free rate. Constant 0.045 is fine for 3-21 DTE (rho-induced delta error <0.005 per quant).
- Crypto options (Deribit pipeline already handles BTC/ETH).
